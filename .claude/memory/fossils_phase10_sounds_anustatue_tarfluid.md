## What shipped (all compile-verified, all live-RCON-verified except where noted)

1. **Sounds backfill**: `sounds.json` was missing 20 of 153 entries (music discs, whip, drum, several dinosaur ambients). Copied the 26 actually-missing `.ogg` files from source into `assets/fossil/sounds/` (1 of the 27 referenced files, `megalodon_hurt0_outside.ogg`, already existed on disk from Phase 6, just wasn't wired into sounds.json) and merged the 20 missing JSON entries in, alphabetically sorted to match existing convention. Verified via a Python script that all 153 entries' sound references resolve to real files — zero unresolved. Also found (but correctly left alone, since it's not referenced by any sounds.json entry in either repo) 7 orphaned unused `.ogg` files in source (`music_anudisc`, deinonychus/gallimimus/megalograptus/meganeura leftovers, `placeholder.ogg`) — don't copy these if revisited, they're dead source assets.
2. **AnuStatueBlockEntity**: was a bare stub (constructor only) — `AnuStatueBlock` didn't even override `getTicker()`, so `serverTick` (already dead code, never called) wouldn't have fired regardless. Ported both the block-entity's `serverTick`/`hasFigurines`/`hasRedstone` logic AND added the missing `getTicker()` override to `AnuStatueBlock`. **Live-verified via RCON**: built a real figurine+redstone+statue altar in a forceloaded test chunk, confirmed the block-entity tick fires deterministically (no player needed — forceloaded chunks tick everything) — explosion happens, all 9 altar blocks clear to air, and a live `fossil:anu_totem` entity spawns with correct attributes (confirmed via `/data get entity`, not just a presence check).
3. **TarFluid**: had zero `tick`/`animateTick` overrides at all (used bare `BaseFlowingFluid.Source`/`Flowing`). Ported `animateParticle` (tar_bubble particles) and `trySpawnTarSlime` (config-gated slime spawning via `Config.spawnTarSlimes`/`Config.tarSlimesSpawnRate`, note: target's `Config` class is a simpler cached-static-field pattern, not source's `FossilConfig.getInt()/isEnabled()` accessor style) plus the ambient tar-bubbling sound on `Flowing.animateTick`. **Live-verified the slime-spawn half via RCON**: placed a `fossil:tar` source block in a forceloaded chunk, waited ~76 real seconds, confirmed a `fossil:tar_slime` entity spawned. The particle/bubbling-sound half (`animateTick`) is architecturally client-only (vanilla `Fluid.animateTick` is never invoked server-side) — this matches source's identical design 1:1, so it's not independently RCON-testable, only compile/code-parity-verified.

## API drift notes worth keeping for future block-entity/fluid work

- `AABB(BlockPos, BlockPos)` two-arg constructor from 1.20.1 is **gone** in 1.21.1 — use `new AABB(BlockPos)` for a unit-cube box at that position (confirmed equivalent via other existing target usages like `PathingRenderUtil`).
- `Mob.finalizeSpawn(ServerLevelAccessor, DifficultyInstance, MobSpawnType, @Nullable SpawnGroupData)` is now **4 args** — 1.20.1 source's trailing 5th `CompoundTag` param is gone.
- `Fluid.tick(Level, BlockPos, FluidState)` and `Fluid.animateTick(Level, BlockPos, FluidState, RandomSource)` signatures are unchanged from source — ports of fluid tick logic are mechanical once you're on `net.neoforged.neoforge.fluids.BaseFlowingFluid.Source/Flowing` instead of Architectury's `ArchitecturyFlowingFluid`.

## Live-testing methodology notes (useful for any future server-side-only mechanic verification)

- **RCON works well for this without a real client**: enabled `enable-rcon`/`rcon.password` in `run/server.properties` temporarily (reverted after), wrote a ~40-line raw-socket Python RCON client (no `mcrcon` lib available), and used `/forceload add` + `/setblock`/`/fill` + `scoreboard`-based boolean checks (NOT `/execute ... run say ...` — `say`'s RCON response payload is empty even on success since it's a chat broadcast with zero players online, a reliable-feeling but actually-useless signal; `scoreboard players get` after `execute if ... run scoreboard players set ... 1` is the reliable pattern) to deterministically trigger and verify server-only game logic (block-entity ticks, fluid ticks, entity spawning) with **zero players connected** — forceloaded chunks tick fully without a player nearby, which is exactly what makes this possible.
- **Known environment gotcha, hit again this session**: running `./gradlew runData` leaves `src/generated/resources/...` behind (gitignored per [[fossils-phase9-task11-wrapup]]'s fix), which duplicates a checked-in file under `src/main/resources` and makes `processResources`/`runServer` fail with "Entry ... is a duplicate". Fix is still just `rm -rf src/generated` before the next `runServer` — this will keep recurring any time `runData` runs before `runServer` in the same session; don't be alarmed, it's not a regression.
- **macOS has no `setsid`** (it's Linux/util-linux only) — don't reach for it to detach background server processes here; plain `nohup ... & disown` was sufficient. Background dedicated-server processes survived independently of the launching Bash tool call's own lifecycle in this environment.
