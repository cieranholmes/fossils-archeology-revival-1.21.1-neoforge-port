### Key MC-1.20.1→1.21.1 API drift discovered this session (reusable knowledge for later phases)
- **`codec()` requirement**: `BaseEntityBlock`, `HorizontalDirectionalBlock`, `BushBlock`, `CrossCollisionBlock` all re-declare `protected abstract MapCodec<? extends X> codec()`, forcing every *concrete* subclass to implement it (usually `simpleCodec(ClassName::new)`; abstract subclasses can skip it). `DoublePlantBlock` and `BedBlock` provide a *concrete* `codec()` already, so their subclasses don't need one. Plain `Block` also has a concrete default. Check this per-superclass when porting any new block type in later phases (this will matter again for entities' block-like helper classes and for any Phase 6 worldgen blocks).
- **`Properties.ofFullCopy(Blocks.X)` / `ofLegacyCopy(Blocks.X)` landmine**: both copy the source vanilla block's `mapColor` function verbatim, including if it's *state-dependent*. `Blocks.BARRIER` and `Blocks.LIGHT` are the only two vanilla blocks using a waterlogged-dependent `mapColor` (`Blocks.waterloggedMapColor(...)`, confirmed via grep across all of `Blocks.java` — no other vanilla block uses it). Copying `Properties` from either of those onto a custom block that doesn't have a `WATERLOGGED` state property throws `IllegalArgumentException: Cannot get property ... waterlogged ... as it does not exist` during block registration, and can cascade into unrelated `NullPointerException: Trying to access unbound value` errors for *other* blocks registered in the same batch (registration failures abort the rest of that registry's batch, not just the one bad entry). **Fix pattern**: append `.mapColor(MapColor.SOMETHING)` after the `ofFullCopy`/`ofLegacyCopy` call to overwrite the inherited function with a constant. Applied to `ANU_BARRIER_ORIGIN`/`ANU_BARRIER_FACE` (both copied from `Blocks.BARRIER`). Audited every other `Properties.ofFullCopy(Blocks.X)` call in `ModBlocks.java` against this specific function (`Blocks.IRON_BARS`, `Blocks.GLASS`, `Blocks.OAK_LEAVES`, `Blocks.OBSIDIAN`, `Blocks.WATER`, `Blocks.DIRT`, `Blocks.CALCITE`/`DEEPSLATE`/`DRIPSTONE_BLOCK`/`RED_SANDSTONE`/`SANDSTONE`/`STONE`/`TUFF`, `Blocks.SLIME_BLOCK` — none of them use it, all safe as originally written).
- `AbstractGlassBlock` no longer exists — `ClearGlassBlock` was rewritten to extend `Block` directly with a manual `skipRendering` override.
- `SaplingBlock` no longer takes `AbstractTreeGrower` (abstract, subclassed per-tree) — it takes a `TreeGrower` (final class, instantiated directly with feature-key `Optional`s). This is a real worldgen-adjacent API change, not just a rename.
- `DoorBlock`/`TrapDoorBlock`/`PressurePlateBlock`/`ButtonBlock`/`FenceGateBlock` constructors reordered to put `BlockSetType`/`WoodType` **first**, before `Properties`. `PressurePlateBlock` and `ButtonBlock` also **dropped** their explicit `Sensitivity`/`arrowsCanPress` params — those are now baked into the `BlockSetType` itself.
- `SandBlock` renamed to `ColoredFallingBlock`, constructor now takes `ColorRGBA` (a record wrapping an int) instead of a raw `int`.
- `DropExperienceBlock` (vanilla) gained a required leading `IntProvider` XP-amount param.
- `BlockBehaviour.Properties.copy(Block)` renamed/split into `ofFullCopy(BlockBehaviour)` and `ofLegacyCopy(BlockBehaviour)` — `ofLegacyCopy` is deprecated, `ofFullCopy` is preferred (this codebase uses `ofFullCopy` throughout).
- `ToolAction`/`ToolActions` → `ItemAbility`/`ItemAbilities`.
- `ItemStack.isSameItemSameTags` → static `ItemStack.isSameItemSameComponents`.
- Old single `use(BlockState,Level,BlockPos,Player,InteractionHand,BlockHitResult)` split into `useItemOn`/`useWithoutItem` (item-agnostic block interactions like opening a GUI now override `useWithoutItem`, which drops the `InteractionHand` param).
- `isPathfindable` dropped its `BlockGetter`/`BlockPos` params (now just `(BlockState, PathComputationType)`).
