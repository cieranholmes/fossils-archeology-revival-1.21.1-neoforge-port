This working directory (`FossilsAndArcheologyRevival`) is a NeoForge-only port of the sibling project `~/IdeaProjects/FossilsArcheologyRevival` (note the similar but distinct name, no "And").

- Source project: MC 1.20.1, Architectury multi-loader setup with `common`/`fabric`/`forge` subprojects, mod id `fossil`, targets both Forge 47.4.3 and Fabric.
- This project: MC 1.21.1, NeoForge 21.1.248 only, Java 21, single-module (no common/fabric/forge split), mod id `fossils`, built from the standard NeoForge MDK template.

**Why:** The user is intentionally dropping Fabric support and the Architectury abstraction layer for this port — NeoForge is the only target platform going forward, not a fourth loader alongside the existing three. Confirmed explicitly (2026-08-07): "I am never going to split it into forge and fabric. I just want to keep it on neoforge."

**How to apply:** When porting features from the 1.20.1 project, translate directly to NeoForge APIs rather than preserving any common/Architectury/multi-loader abstraction. Never propose or scaffold a common/fabric/forge module split, Architectury plugins, or multi-loader-friendly code (e.g. platform-agnostic interfaces solely for loader abstraction) for this project — it's a single-module NeoForge-only codebase by firm decision, not an open question. As of 2026-08-09, Phase 0 of [[fossils-migration-plan]] is complete: hard dependencies (GeckoLib 4.9.2, TerraBlender 4.1.0.8, more-hitboxes 1.9.4-alpha) are wired into `build.gradle`/`gradle.properties` and declared as required deps in `neoforge.mods.toml`; mixin loading is wired via `fossils.mixins.json` (JAVA_21, currently empty — no mixins ported yet) referenced from `neoforge.mods.toml`'s `[[mixins]]` block; `FossilsAndArcheologyRevival.java` is the single merged `@Mod` entry class (constructor-injected `IEventBus`/`ModContainer`, no packets/capabilities/registries yet); `Config.java` has the full common+client `ModConfigSpec` ported from the source's `ForgeConfig`/`FossilConfig` (the old `@ExpectPlatform` indirection, MidnightConfig translation keys, and the Forge config-version-fix migration system were all dropped as unneeded for a fresh single-platform port). Phase 0 was verified by a clean `compileJava` and a full `runServer` boot (`Done (Xs)!`) with all 4 mods (fossils/geckolib/terrablender/morehitboxes) discovered and loaded.

**Phase 1 (Blocks) is complete and verified as of 2026-08-09:** see [[fossils-phase1-blocks-progress]] for the detailed breakdown — `ModBlocks.java` (217 of source's 221 blocks; 4 deliberately deferred to later phases) plus ~14 missing custom block classes and a wave of MC-1.21.1 API-drift fixes were completed. `compileJava` succeeds with 0 errors and `runServer` boots clean to `Done (1.177s)!` with no errors/warnings and all 4 mods loaded.
